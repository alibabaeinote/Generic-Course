## ۲. دامنه و DNS

1. ثبت دامنه (D9). اگر مخاطب داخل ایران است، هم `.com` و هم `.ir` رزرو شود.
2. DNS روی ارائه‌دهندهٔ منتخب (ابرآروان در مسیر A، Cloudflare در مسیر B).
3. رکوردها: `A/CNAME` برای ریشه و `www`، `CNAME` برای `staging`.
4. SSL خودکار (Let's Encrypt) + اجبار HTTPS + HSTS.
5. یک نسخهٔ canonical انتخاب شود (`www` یا بدون `www`) و بقیه ۳۰۱ شوند.
6. رکوردهای ایمیل (SPF/DKIM/DMARC) برای ایمیل تراکنشی، تا پیام‌های تأیید در اسپم نیفتند.

## ۳. خط لولهٔ استقرار

```
push to feature branch → CI: lint + typecheck + test + build
        ↓ merge to main
   deploy خودکار به staging (noindex)
        ↓ تأیید دستی
   deploy به production + tag نسخه
```

- **Rollback:** نگهداری نسخهٔ قبلی و امکان بازگشت یک‌کلیکی/یک‌دستوری. هر فاز جدا rollback می‌شود (الزام PRD).
- **Migration:** پیش از deploy اجرا می‌شود؛ backward compatible نوشته می‌شود تا rollback اپ، دیتابیس را نشکند.
- **Secrets:** فقط در محیط هاست؛ هرگز در ریپو. `.env.example` بدون مقدار نگهداری می‌شود.
- **بکاپ:** بکاپ روزانهٔ خودکار دیتابیس از روزی که اولین ایمیل لیست انتظار ثبت می‌شود.

## ۵. روز انتشار

1. دیپلوی در ساعت کم‌ترافیک، نه شب جمعه.
2. تست دستی مسیر اصلی روی یک موبایل واقعی: باز کردن سایت → خواندن → ثبت در لیست انتظار → دریافت پیام تأیید.
3. باز کردن ترافیک: انتشار در شبکه‌های اجتماعی مدرس با UTM مشخص (`?utm_source=...`) تا `source` در
   `WaitlistEntry` معنادار باشد.
4. پایش ۴۸ ساعت اول: خطاهای سرور، نرخ ثبت‌نام، نرخ خروج از Hero، سرعت واقعی.
5. اولین بازبینی محتوایی ۷۲ ساعت بعد از لانچ، بر پایهٔ داده نه سلیقه.
