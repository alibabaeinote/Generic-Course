## ۱. الان چه چیزی تصمیم گرفته می‌شود، چه چیزی بعداً

| الان تصمیم می‌گیریم | بعد از انتخاب جهت بصری |
|---|---|
| معماری و نام‌گذاری توکن‌ها | مقدار رنگ‌ها |
| نسبت و پله‌های مقیاس تایپ | خانوادهٔ فونت و وزن‌ها |
| پله‌های فاصله و شبکه | شعاع گوشه‌ها |
| قواعد RTL | سایه و عمق |
| فهرست کامپوننت‌ها و اولویتشان | جنس حرکت (کشسان یا خطی) |
| ماتریس حالت‌ها | سبک آیکون و تصویرسازی |
| کف دسترسی‌پذیری | — |
| ساختار فایل و نام‌گذاری | — |

**قاعده:** هیچ مقدار رنگ یا فونتی مستقیم در کامپوننت نوشته نمی‌شود. همه از توکن می‌آیند. پس عوض کردن جهت
بصری یعنی عوض کردن یک فایل، نه بازنویسی محصول.

## ۲. معماری توکن‌ها — سه لایه

```
لایهٔ ۱ — Primitive    مقدار خام، بی‌معنی      --c-blue-600, --space-4, --text-3
لایهٔ ۲ — Semantic     نقش، مستقل از مقدار     --bg-surface, --text-muted, --border-subtle
لایهٔ ۳ — Component    کاربرد مشخص             --btn-primary-bg, --card-padding
```

**کامپوننت‌ها فقط از لایهٔ ۲ و ۳ استفاده می‌کنند. هرگز از لایهٔ ۱.**
این کاری می‌کند که تم روشن/تاریک و تعویض جهت بصری، هر دو با بازتعریف یک لایه انجام شوند.

### نام‌گذاری معنایی (قطعی، مستقل از مقدار)

| نقش | توکن |
|---|---|
| زمینهٔ صفحه | `--bg-page` |
| زمینهٔ سطح (کارت، پنل) | `--bg-surface` |
| زمینهٔ فرورفته | `--bg-sunken` |
| زمینهٔ معکوس (سکشن تیره) | `--bg-inverse` |
| متن اصلی | `--text-primary` |
| متن ثانویه | `--text-muted` |
| متن کم‌رنگ | `--text-subtle` |
| متن روی سطح معکوس | `--text-on-inverse` |
| خط جداکننده | `--border-subtle` / `--border-strong` |
| رنگ کنش اصلی | `--accent` / `--accent-contrast` |
| موفقیت / هشدار / خطا | `--success` / `--warning` / `--danger` |

> رنگ‌های معنایی (موفق/هشدار/خطا) از رنگ لهجهٔ برند **جدا** هستند و با تغییر جهت بصری عوض نمی‌شوند.

## ۳. مقیاس‌ها

### فاصله — پایهٔ ۴ پیکسل
```
space-1  4    space-2  8    space-3  12   space-4  16   space-5  24
space-6  32   space-7  48   space-8  64   space-9  96   space-10 128
```
هیچ فاصله‌ای خارج از این پله‌ها استفاده نمی‌شود.

### تایپوگرافی — مقیاس سیال
هفت پله، هر کدام با `clamp()` بین موبایل و دسکتاپ. **نسبت‌ها الان تعیین می‌شوند، فونت بعداً.**

| پله | کاربرد | نسبت به بدنه |
|---|---|---|
| `text-display` | تیتر Hero | ۶× تا ۹× |
| `text-h1` | تیتر سکشن | ۳× تا ۴.۵× |
| `text-h2` | تیتر فرعی | ۱.۸× تا ۲.۵× |
| `text-h3` | تیتر کارت | ۱.۲× تا ۱.۵× |
| `text-lede` | پاراگراف شاخص | ۱.۱× تا ۱.۳× |
| `text-body` | متن بدنه | ۱× (پایه ۱۷px) |
| `text-caption` | برچسب و توضیح | ۰.۸۵× |

**قاعدهٔ فارسی:** ارتفاع خط تیترهای بزرگ هرگز زیر ۱.۲۵ نمی‌رود و بدنه زیر ۱.۸ نمی‌آید. فارسی کشیدگی
عمودی بیشتری از لاتین دارد؛ فاصلهٔ خط لاتین برای فارسی خطوط را روی هم می‌اندازد. *(این را در عمل دیدیم.)*

### سایر مقیاس‌ها
- **شعاع:** چهار جای خالی — `radius-sm / md / lg / pill`. مقدارها پس از انتخاب جهت.
- **لایه (z-index):** `base 0 · sticky 20 · overlay 40 · modal 60 · toast 80`
- **نقاط شکست:** `sm 480 · md 768 · lg 1024 · xl 1280`
- **عرض محتوا:** `measure 46ch` برای پاراگراف · `container 82rem` برای صفحه
- **مدت حرکت:** `fast 180ms · base 320ms · slow 600ms · reveal 900ms`

## ۴. قواعد RTL — غیرقابل مذاکره

۱. **فقط ویژگی‌های منطقی.** `padding-inline-start` نه `padding-left`. `inset-inline-end` نه `right`.
   استثنا: عنصری که خودش `writing-mode` عمودی دارد — آنجا از سمت صریح استفاده کن *(این هم در عمل ما را گرفت)*.
۲. **اصطلاح لاتین با `unicode-bidi: isolate`** پیچیده شود، وگرنه در متن فارسی جابه‌جا می‌شود.
۳. **آیکون‌های جهت‌دار قرینه می‌شوند:** فلش، بازگشت، پیشرفت، مرتب‌سازی.
   **قرینه نمی‌شوند:** ساعت، علامت تیک، ذره‌بین، آیکون رسانه (پخش/توقف)، لوگو.
۴. **اعداد ترتیبی** (شمارهٔ سکشن، پله) در ستون‌ها با `font-variant-numeric: tabular-nums`.
۵. هر کامپوننت باید در عرض ۳۲۰ پیکسل بدون اسکرول افقی درست باشد.

## ۶. ماتریس حالت‌ها

هیچ کامپوننت تعاملی «تمام» نیست تا وقتی این حالت‌ها تعریف شوند:

| حالت | الزام |
|---|---|
| `default` | حالت پایه |
| `hover` | فقط روی نشانگر دقیق (`hover: hover`) |
| `active` | لحظهٔ فشردن |
| `focus-visible` | **الزامی** — با کیبورد باید دیده شود |
| `disabled` | با دلیل؛ اگر معلوم نیست چرا غیرفعال است، غیرفعالش نکن |
| `loading` | برای هر کنشی که بیش از ۴۰۰ms طول می‌کشد |
| `error` | با متن، نه فقط رنگ |
| `empty` | متنش از کتابخانهٔ میکروکپی می‌آید |
| `success` | تأیید صریح، نه فقط بستن پنجره |

## ۷. کف دسترسی‌پذیری

- کنتراست متن اصلی ≥ ۴.۵:۱ · متن درشت ≥ ۳:۱ · مرز عناصر تعاملی ≥ ۳:۱
- ناحیهٔ لمس حداقل ۴۴×۴۴ پیکسل
- `focus-visible` روی همه‌چیز، با ضخامت حداقل ۲px و فاصله از عنصر
- هر ورودی `label` واقعی دارد — `placeholder` جای برچسب نیست
- خطا با متن اعلام می‌شود، نه فقط با رنگ قرمز
- ترتیب تب منطقی و مطابق ترتیب بصری
- `prefers-reduced-motion` کل سیستم حرکت را خاموش می‌کند
- سلسله‌مراتب تیترها بدون پرش (h1 → h2 → h3)

## ۸. ساختار فایل و نام‌گذاری

```
styles/
  tokens/
    primitive.css      لایهٔ ۱ — مقدار خام
    semantic.css       لایهٔ ۲ — نقش‌ها (و بازتعریف تم تاریک)
    theme-<name>.css   جهت بصری انتخابی — تنها فایلی که با تغییر سبک عوض می‌شود
  base/
    reset.css · typography.css · rtl.css
  components/
    button.css · card.css · accordion.css · …
```

- **نام کلاس:** `block__element--modifier` (`card__title--muted`)
- **نام توکن:** `--<category>-<role>-<variant>` (`--text-muted`, `--btn-primary-bg`)
- هر کامپوننت یک فایل، و همان فایل همهٔ حالت‌هایش را دارد.

## ۹. قدم‌های اجرایی

| # | قدم | خروجی |
|---|---|---|
| ۱ | ممیزی محتوای موجود و استخراج هر الگوی تکرارشونده از چهار پیش‌نویس | فهرست واقعی کامپوننت‌ها (نه حدسی) |
| ۲ | نوشتن `primitive.css` و `semantic.css` با مقدارهای موقت خاکستری | سیستم کار می‌کند، بی‌آنکه سبکی داشته باشد |
| ۳ | ساخت `rtl.css` و تست فارسی: نیم‌فاصله، ارقام، اصطلاح مختلط، ۳۲۰px | پایهٔ زبانی درست |
| ۴ | ساخت هشت کامپوننت P0 با **همهٔ** حالت‌های بخش ۶ | کیت فاز ۱ |
| ۵ | ساخت صفحهٔ داخلی `/styleguide` که همهٔ کامپوننت‌ها و حالت‌هایشان را نشان می‌دهد | جای بازبینی و تست دسترسی‌پذیری |
| ۶ | **انتخاب جهت بصری** و نوشتن `theme-<name>.css` | محصول ظاهر پیدا می‌کند |
| ۷ | ساخت لندینگ روی کیت آماده | فاز ۱ |

قدم ۶ تنها جایی است که به تصمیم بصری نیاز دارد. **قدم‌های ۱ تا ۵ همین حالا قابل شروع‌اند.**
