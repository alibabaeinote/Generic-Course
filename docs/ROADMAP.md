## M0 — تثبیت محتوا و تصمیم‌ها

**چرا اول:** بزرگ‌ترین ریسک این پروژه فنی نیست؛ نوشتن است. اگر کد قبل از متن نوشته شود، لِی‌اوت به متن تحمیل
می‌شود و روایتِ خواسته‌شده در PRD («سردرگمی → نگاه → مسیر → صداقت → جزئیات → اقدام») از بین می‌رود.

**ورودی‌های لازم از مالک محصول**

- [ ] ساختار محتوای صفحهٔ اصلی — قالب آماده: [`content/homepage-brief.md`](content/homepage-brief.md)
- [ ] متن نهایی bio و اعتبارهای **قابل تأیید** (بدون ادعای اثبات‌نشدنی)
- [ ] تصمیم دربارهٔ نمایش قیمت در فاز ۱ (عدد قطعی / بازهٔ تقریبی / «به‌زودی»)
- [ ] وضعیت فعلی دوره: `upcoming` یا `open` یا `waitlist`
- [ ] تاریخ و ظرفیت واقعی cohort اول
- [ ] بستن تصمیم‌های بلوکر در [`DECISIONS.md`](DECISIONS.md) — به‌ویژه D1 (مخاطب/هاست)

**خروجی**

- `content/course.ts` و متن سکشن‌ها به‌صورت نهایی (نه Lorem).
- ۸ تا ۱۲ سؤال FAQ با پاسخ نوشته‌شده.
- تعیین‌تکلیف سه سؤال سختِ صداقت: این دوره برای چه کسی **مناسب نیست**؟ چه چیزی را تضمین **نمی‌کند**؟ سطح تعهد
  هفتگی چقدر است؟

**Done وقتی:** کل متن سایت در یک فایل قابل خواندن است و مالک محصول آن را بلند خوانده و تأیید کرده.

## M1 — پی‌ریزی فنی و زبان بصری

- راه‌اندازی Next.js + TypeScript + Tailwind v4 + ESLint/Prettier + strict mode.
- `dir="rtl"` و `lang="fa"` در ریشه؛ ممیزی اینکه هیچ فاصله‌گذاری فیزیکی (`ml-`, `pr-`) استفاده نشود.
- بارگذاری Kalameh به‌صورت self-hosted با subset فارسی + `font-display: swap` + fallback.
- توکن‌های دیزاین: مقیاس تایپوگرافی (تیتر بسیار بزرگ تا متن بدنه)، مقیاس فاصله، پالت، شعاع، سایه، breakpointها.
- کامپوننت‌های پایه با accessibility از روز اول: `Button`, `Field`, `Accordion`, `Dialog`, `SkipLink`.
- اسکلت آنالیتیکس: `track(event, payload)` با قرارداد [`ANALYTICS.md`](ANALYTICS.md).
- GitHub Actions: lint + typecheck + build روی هر PR.

**Done وقتی:** یک صفحهٔ نمونه با تیتر بزرگ فارسی، دکمه و فرم روی موبایل و دسکتاپ درست است، با کیبورد قابل
پیمایش است و Lighthouse در محدودهٔ هدف قرار دارد.

## M2 — ساخت فاز ۱

سکشن‌ها به ترتیب روایت ساخته می‌شوند، نه به ترتیب سهولت:

1. Hero — پیام اصلی + وضعیت دوره + CTA اصلی
2. روایت مسئله — سردرگمی مخاطب
3. فلسفهٔ دوره — مدل آگاهی → مهارت → میدان
4. مسیر یادگیری — سرفصل‌ها در سطح «کاربر چه به‌دست می‌آورد»
5. صداقت — این دوره چه چیزی نیست
6. مناسب برای / مناسب نیست برای
7. معرفی مدرس
8. جزئیات دوره — فرمت، مدت، تعهد، قیمت
9. FAQ
10. CTA پایانی + Footer + لینک‌های قانونی

**کارهای فنی موازی**

- CTA بیرونی: `enrollUrl` در `content/course.ts`، باز شدن در تب جدید با `rel="noopener"`، و ثبت رویداد خروج.
  در v1 هیچ فرم، دیتابیس یا ایمیل تراکنشی ساخته نمی‌شود (تصمیم D-scope).
- SEO: metadata مستقل هر صفحه، OG image، `sitemap.xml`، `robots.txt`، canonical، JSON-LD نوع `Course`.
- تست‌های Playwright به ازای هر Acceptance Criterion فاز ۱.
- صفحات `privacy` و `terms` (چون داده جمع‌آوری می‌شود، الزامی است).

**Done وقتی:** هر ۷ مورد Acceptance Criteria فاز ۱ در PRD تست خودکار یا بازبینی ثبت‌شده دارد.

## M4 — فاز ۲: ثبت‌نام و پرداخت

ترتیب اجرا (هر قدم مستقل قابل تست):

1. **مدل داده و migration:** `User`, `CourseRun`, `Enrollment`, `Order`, `PaymentEvent`.
2. **ورود/ثبت‌نام:** OTP، session امن، rate limit، مهاجرت idempotent از `WaitlistEntry`.
3. **صفحات دوره:** `/courses` و `/courses/:slug` با ظرفیت زنده.
4. **رزرو ظرفیت:** رزرو موقت با timeout؛ تست همزمانی برای «بیش‌فروشی نشدن».
5. **درگاه پرداخت:** پشت آداپتور `lib/payment`؛ sandbox اول.
6. **Webhook:** منبع حقیقت وضعیت پرداخت، با `provider_event_id` یکتا برای idempotency.
7. **حالت‌های نتیجه:** success / failed / pending با قدم بعدی روشن برای کاربر.
8. **ایمیل/پیامک تأیید** و رسید در `/account`.
9. **`/admin/applicants`** با authorization سمت سرور و فیلتر.
10. **Audit log** برای سفارش، پرداخت و تغییر enrollment.

**ریسک اصلی:** بیش‌فروشی ظرفیت و سفارش‌های گیرکرده در `pending`. هر دو باید تست اختصاصی داشته باشند.

## M5 — فاز ۳: پنل یادگیرنده (MVP)

فقط برای cohort اول و فقط تا حدی که آن cohort را زنده نگه دارد:

1. `/learn` dashboard با «ادامه از آخرین نقطه»
2. ساختار `module → lesson` + وضعیت انتشار (`draft` هرگز به learner نشان داده نمی‌شود)
3. `session` با زمان و لینک جلسه/ضبط
4. `assignment` + `submission` (فایل/لینک/متن) با نسخه‌بندی و امضای موقت URL
5. `feedback thread` روی همان submission
6. `/mentor/reviews` صف بررسی
7. `progress` محاسبه‌شده از دادهٔ خام، نه ذخیرهٔ جداگانه
8. اعلان حداقلی: feedback جدید، نزدیک شدن deadline

**آنچه در MVP ساخته نمی‌شود:** چت، ویدیوکنفرانس داخلی، نمره، community، اپ موبایل.
